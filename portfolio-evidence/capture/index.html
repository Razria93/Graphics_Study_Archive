조건과 판정 기준

  1. 정상 상태: 오류 없이 일반 창만 표시. 코드 0이며 일반 창이 유지돼야 함.
  2. 순차 오류: 기본 MessageBox A를 닫아야 B를 호출. 코드 0, 후속 창 판정, 오류 잔존 0개를 확인.
  3. 지연 오류: A 종료 후 원본의 Outcome: Quiet 출력을 관찰한 시점에 신호를 보내고, 0.5초 뒤 B 표시. 안정 대기 뒤 코드 3과 B 잔존을 보고해야 함. 재현 타이밍을 맞추는 신호는 테스트 장치에만 적용.
  4. 종료 거부: 테스트 Form의 FormClosing에서 종료 요청을 취소. 코드 3과 StillPresent 판정으로 중단해야 함.
  5. 일반 창 동시 표시: 같은 프로세스에서 순차 오류와 일반 Form을 함께 표시. 오류만 정리하고 일반 창은 유지돼야 함.

지연 오류·종료 거부의 통과는 실패를 정확히 보고했다는 뜻입니다. 자동 복구 성공으로 세지 않습니다. 정리 도구는 종료 코드를 반환하며, 실제 호출자가 그 코드를 무시하면 다음 실행 차단을 보장하지 못합니다.

확인한 한계

  • 안정 대기 중 나타난 B는 감지하고 실패로 종료하지만, 그 시점에 다시 정리하는 자동 재시도는 하지 않습니다.
  • 설정한 관찰 시간이 끝난 뒤 더 늦게 생기는 오류까지 보장하지 않습니다. 초기 조회에 오류가 없으면 원본 정리 도구는 바로 코드 0을 반환합니다.
  • 일반 창 유지 검증은 지정한 테스트 프로세스의 일반 Form에 대한 결과입니다. 동일 프로세스의 모든 시스템 대화상자를 구분해 보호했다는 뜻이 아닙니다. 원본 후보 조건에는 기본 대화상자 클래스 #32770도 포함됩니다.
  • 실제 DLL 로딩 실패, Clean/Rebuild, 원래 그래픽스 예제 및 촬영 재개는 이번 검증 범위에 포함하지 않았습니다.
  • 각 조건 3회는 반복 동작 확인이며 환경 전체에 대한 안정성 통계는 아닙니다.

별도 기존 회귀 테스트 기록

원본 테스트는 두 동시 오류 창을 정리한 뒤의 외부 5초 대기 검사에서 실패했습니다. 순차 오류 단계까지 도달하지 못했습니다. 성공 조건의 시간 제한만 5초에서 15초로 바꾼 별도 사본은 통과했습니다. 조용한 상태의 필요 시간과 검증 조건은 유지했습니다. 원본 테스트 전체 통과로 표현하지 않습니다.

시간 제한 실패의 원인은 계측으로 확정하지 못했습니다. 새 PowerShell 조회 프로세스의 비용이 관련될 수 있지만 확인된 원인으로 단정하지 않습니다. 이 결과는 위의 15회와 별도입니다.

영상의 역할

개선 전·후 비교 재현 영상은 현상과 절차를 설명합니다. 기본 Windows 창과 MessageBox를 사용하지만 시연용 프로그램이며, 실제 DLL 오류나 위 원본 정리 스크립트를 실행한 영상은 아닙니다. 검증 근거는 위 실행 로그와 창 상태입니다.

공개 자료 범위

비교 영상과 검증 결과 및 필요한 판정 필드를 공개한다. 원본 로그·호출 스크립트·압축 자료는 로컬 검증 자료로 보존한다.
