# Demo Issues

이 폴더는 Demo Issue 정본을 둔다.

## 파일명 규칙

- `demo_<slug>.md`

## 생성 기준

- screenshot, video, result image 제작이나 승인 범위가 별도 작업일 때 생성한다.

## 작성 기준

- 첫 H1을 title source로 유지한다.
- PR 본문 요약으로 부족한 시각 자료와 구현 개괄을 보강한다.
- screenshot/video/result image 목록과 각 파일이 무엇을 보여주는지 설명한다.
- 핵심 목표, 처리 흐름, key code map을 포함해 구현 관점을 함께 제공한다.
- 구현 설명은 하이라이트 중심으로 제한하고 상세 구현은 링크로 위임한다.
- 코드 섹션은 원문 복제보다 의사코드 중심 요약을 우선한다.
- 의사코드는 가능하면 C++ 스타일 문법(함수, for, if, 블록)으로 작성해 읽기 흐름을 유지한다.
- 의사코드는 핵심 구조(입력, 처리 단계, 출력, 실패 분기)만 보여주고 세부 구현은 생략한다.
- 의사코드 한 줄 길이는 약 80자 내외를 권장하고, 긴 식은 2~3줄로 분해한다.
- 각 의사코드 블럭 아래에 원본 라인 링크를 반드시 둔다.
- 검증 상태는 요약 2~3줄로 유지한다.
- 토픽 이론 설명은 `Docs/01_Topics`로 위임하고, Demo Issue는 시각 정보와 구현 개괄 중심으로 유지한다.
- capture/result 상세 근거는 `Docs/03_Demos` 정본으로 연결한다.

## PR 연계 기준

- PR 본문은 demo를 간단히 소개하고 Demo Issue 링크를 중심으로 연결한다.
- Demo Issue는 시각 자료, 구현 하이라이트, 코드 링크를 중심으로 유지한다.
